# 仪表盘可视化与数据导出设计

## 目标

在不改变现有仪表盘数据接口的前提下，为学生、教师和管理员提供角色适配的数据图表；同时由后端生成 CSV 和 Excel 文件，保证导出内容与访问权限一致。

本期不引入班级和学科实体，但所有统计与导出逻辑都以可扩展的数据范围边界实现，为后续细粒度权限管理留出入口。

## 范围

### 本期包含

- 前端接入 ECharts，并在现有仪表盘中按角色展示图表。
- 后端新增仪表盘导出接口，支持 CSV 和 XLSX。
- 前端增加 Excel 和 CSV 的下载入口及请求状态反馈。
- 导出服务按当前登录用户执行数据范围限制。
- 为图表配置和导出权限补充自动化测试。
- 新增本设计文档中定义的班级、学科管理后续扩展方案。

### 本期不包含

- 班级、学科、选课或学生分班的数据库和页面实现。
- 按日、周、月的历史趋势接口。
- 将图表渲染为图片后嵌入导出文件。
- 修改现有 `/api/statistics/dashboard` 返回结构。

## 数据与图表

图表继续请求 `GET /api/statistics/dashboard`。首版仅使用已有字段，不增加趋势统计接口。

| 角色 | 图表 | 使用字段 | 呈现方式 |
| --- | --- | --- | --- |
| 学生 | 最近成绩与及格线 | `recent_records.score`、`recent_records.pass_score`、`recent_records.exam_title` | 分组柱状图 |
| 学生 | 通过率 | `stats.pass_rate` | 环形图 |
| 教师 | 各考试待批改数量 | `pending_grading.exam_title`、`pending_grading.pending_count` | 横向柱状图 |
| 教师 | 最近考试 | `recent_exams.title`、`recent_exams.start_time`、`recent_exams.status` | 时间线 |
| 管理员 | 用户角色分布 | `role_distribution.role`、`role_distribution.count` | 环形图 |

无对应数据时，图表区域显示现有空状态组件，而不是渲染空白画布。图表使用固定的容器高度和响应式宽度；窗口变化时调用 ECharts 的 `resize`。

## 前端设计

- 安装 `echarts`，封装一个仅负责初始化、更新和销毁图表实例的可复用组件。
- 图表置于仪表盘统计卡片之后、现有业务列表之前；页面保持现有 `PageCard`、间距、色彩和空状态样式。
- 角色图表各自封装 option 构建函数，避免在页面组件中混合数据转换与布局代码。
- 页面右上方增加带下载图标的导出下拉菜单，提供“导出 CSV”和“导出 Excel”。下载期间显示按钮加载状态，失败时显示现有错误提示。
- Excel 和 CSV 均从后端以 Blob 形式下载，前端从 `Content-Disposition` 读取文件名，缺失时使用固定中文文件名兜底。

## 后端导出设计

新增认证接口：

```text
GET /api/statistics/dashboard/export?format=csv|xlsx&dataset=[optional]
```

参数规则：

- `format` 必填，值为 `csv` 或 `xlsx`；其他值返回 400。
- `dataset` 仅适用于 CSV，用于选择一个数据集；省略时导出“概览”。
- XLSX 忽略 `dataset`，始终导出当前角色允许的全部工作表。

响应规则：

- CSV 使用 `text/csv; charset=utf-8`，带 UTF-8 BOM，保证中文软件兼容。
- XLSX 使用标准 Office Open XML MIME 类型。
- 两种格式均以 `Content-Disposition: attachment` 返回，并使用安全文件名。

服务层拆分为三个职责：

1. `get_dashboard_data`：保留现有页面数据组装职责。
2. `get_dashboard_export_datasets`：按当前用户生成结构化、可导出的数据集。
3. `render_dashboard_export`：把数据集渲染为 CSV 或 XLSX 二进制内容。

Excel 使用 `openpyxl` 生成工作簿。工作表规则如下：

| 角色 | 工作表 |
| --- | --- |
| 学生 | 概览、最近成绩、即将开始考试 |
| 教师 | 概览、待批改、最近考试 |
| 管理员 | 概览、角色分布、最近注册用户 |

CSV 一次导出一个数据集，避免把多个异构表格拼接进单一文件。`dataset` 的可选值由服务端根据当前角色校验；不允许的值返回 400，而不是暴露其他角色数据。

## 权限与数据范围

导出不得接受用户 ID、教师 ID、课程 ID 等用于扩张查询范围的客户端参数，范围完全由当前认证用户计算：

- 学生：`ExamRecord.student_id == current_user.id`。
- 教师：先获取 `Course.teacher_id == current_user.id` 的课程，再限制考试、答卷和待批改答案到这些课程。
- 管理员：可读取全局用户、考试及统计数据。

这一规则与现有仪表盘的角色分支一致。新增导出服务必须独立重建查询范围，不能信任前端已加载的仪表盘响应。

## 后续班级与学科扩展

### 目标模型

后续新增以下实体和关联：

| 实体/关联 | 关键字段 | 用途 |
| --- | --- | --- |
| `Subject` | `id`、`name`、`code` | 定义学科，如计算机网络或高等数学。 |
| `Class` | `id`、`name`、`grade`、`academic_year` | 定义行政班或教学班。 |
| `StudentClass` | `student_id`、`class_id`、`joined_at`、`left_at` | 记录学生在一个时间段内的班级归属。 |
| `CourseSubject` 或 `Course.subject_id` | 课程与学科关联 | 标记课程所属学科。 |
| `CourseClass` | `course_id`、`class_id` | 将课程授课范围分配给一个或多个班级。 |
| `ExamClass` | `exam_id`、`class_id` | 将考试发布范围限制到指定班级。 |

当一个课程只属于一个学科时，优先采用 `Course.subject_id`；如果课程需要跨学科标签，再改用多对多 `CourseSubject`。

### 权限演进

当前权限范围是：

```text
角色 + 资源所有者
```

引入班级和学科后演进为：

```text
角色 + 资源所有者 + 学科范围 + 班级成员关系
```

具体规则：

- 学生只能查看 `ExamClass` 包含其当前有效班级的已发布考试；个人成绩仍按 `ExamRecord.student_id` 限制。
- 教师只能管理自己负责课程的班级范围内的考试和答卷；教师跨班授课通过 `CourseClass` 表达。
- 管理员可维护学科、班级、学生分班和课程分班，并保留全局可见性。

### 迁移顺序

1. 新增班级和学科表，不修改现有课程、考试和答卷数据。
2. 为现有课程补充学科，并建立课程到班级的关联。
3. 为学生建立有效的班级成员记录。
4. 为考试建立发布班级关联，并在学生考试列表中启用班级筛选。
5. 将仪表盘和导出服务的“数据范围”实现扩展为可选班级、学科过滤。
6. 补充跨班级、跨学科、退班学生和历史成绩可见性的权限测试。

在第 1 至第 4 步完成前，保留当前“所有已发布考试对所有学生可见”的兼容行为，避免迁移期间意外隐藏考试。

## 测试与验收

- 前端：按三个角色分别验证正确的图表、空状态和导出入口；验证下载失败提示。
- 后端：验证 CSV/XLSX 内容类型、文件名、工作表/列头，以及三种角色只能获取授权数据集。
- 权限：学生不能请求教师或管理员数据集；教师不能导出非本人课程的数据。
- 回归：保留现有仪表盘接口响应和页面列表行为。

验收条件是三种角色都能看到与其现有仪表盘数据一致的图表，且能成功下载权限范围内的 CSV 和 XLSX 文件。
